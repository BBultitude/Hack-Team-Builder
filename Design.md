# Hack Team Builder: build specification

## 1. Purpose
Mobile-first static web app helping a player of GBA Pokémon ROM hacks (Unbound, Emerald Rogue, etc.) build a balanced team from Pokémon they own, and pick the best party member against an opponent. It uses vanilla (unmodified official game) data for Generations (Gen) 1–9 as a baseline. Hack differences are handled by manual edits. Per-hack datasets were dropped as unmaintainable.

## 2. Decisions already made
- Vanilla data only; user edits types, ability, moves and base stats per Pokémon.
- Moves: "level B" (known moves plus learnable-move suggestions). No full damage calculator.
- Opponent tab is simple: best member, worst member, plain-English reasons.
- Define every acronym once (STAB = Same-Type Attack Bonus: 1.5× damage when a move's type matches the user's type). Use full stat names (Attack, Special Attack, Speed).
- Australian English. Concise professional tone.
- Prototype is a single HTML file, with all data inlined (hosting blocks external requests).

## 3. Data (build-time pipeline)
Source: PokeAPI CSVs (github.com/PokeAPI/pokeapi, data/v2/csv): pokemon, pokemon_types, pokemon_stats, pokemon_abilities, abilities, moves, pokemon_moves.
- Species: ids ≤ 1025 plus alternate forms (Mega, regional) only where types differ from the base species; exclude Gigantamax; skip entries with no types.
- Per entry: name, 1–2 types, 6 base stats (Hit Points, Attack, Defense, Special Attack, Special Defense, Speed), abilities (flag hidden).
- Moves: damaging only (damage class physical/special, id < 10000), including power 0/variable. 648 moves with name, type, power.
- Learnsets: union of all version groups per species; forms without their own moves reference the base species.
- Plus 18 pseudo-moves "Any [Type] move" (power 80) for hacks that retype or rename moves.
- Type chart: 18 types including Fairy. Type order: Normal, Fire, Water, Electric, Grass, Ice, Fighting, Poison, Ground, Flying, Psychic, Bug, Rock, Ghost, Dragon, Dark, Steel, Fairy.
- 25 natures: +10% to one stat, −10% to another, or neutral.
- Prototype size is about 165 KB (about 1,133 entries). In a real app, ship as JSON files, versioned, generated by a script that is re-runnable.

## 4. Roster entry (persisted, key "ptb2" in localStorage)
{ n: name, a: type1, b: type2 or -1, ab: ability, nt: nature index, mv: [4 move names], st: 6 stat overrides or null, d: dex index or -1 (custom Pokémon) }
Also persisted: team (indices, max 6), opponent {name, ability}, rank scope ("team" or "all").

## 5. Features and logic
**Add Pokémon:** searchable by name (autofills types, abilities); custom types allowed.
**Per-Pokémon edit:** ability, nature, 4 moves (any move allowed, with a note if not in the vanilla learnset), 6 base stats (marked "modified from vanilla" with a reset button).
**Effective stat:** base × 1.1 or 0.9 for nature. Role: Physical if Attack > Special Attack × 1.15, Special if the reverse, else Mixed.
**Ability effects modelled:**
- Immunities: Levitate, Earth Eater (Ground); Flash Fire, Well Baked Body (Fire); Water Absorb, Storm Drain, Dry Skin (Water); Volt Absorb, Lightning Rod, Motor Drive (Electric); Sap Sipper (Grass).
- Halve: Thick Fat (Fire, Ice); Heatproof, Water Bubble (Fire); Purifying Salt (Ghost).
- Wonder Guard: only super-effective hits land.
- Filter, Solid Rock, Prism Armor: ×0.75 on super-effective hits.
- Attacker-side abilities (Mold Breaker, etc.) are not modelled.
**Team analysis (up to 6):**
- Defensive grid: for each of 18 attack types, count weaknesses and resistances per member (ability applied).
- Per member and type multiplier x: x ≥ 3 → weak +2, score −2; x > 1 → weak +1, −1; x = 0 → resist +1, +1.5; x ≤ 0.5 → resist +1, +1. If 3+ weaknesses and weak > resist: −2.
- Offensive coverage: count of 18 types hit super-effectively by any attack option. Options are the entered moves' types, or own types (STAB) if none entered.
- Team score = defensive + 1.5 × coverage.
- Also shown: exposed types, uncovered types, physical/special balance, suggested next additions (score gain), warning if abilities unset.
- Recommended moves (advice only): four learnable moves per member, greedy on power × STAB 1.5 × role fit (0.6 off-role) + 40 per type newly hit super-effectively; members share one coverage set so they complement each other. Self-KO, recharge and charge-up moves excluded.
**Evolve:** each Pokémon shows its vanilla evolution method(s); "Evolve → X" swaps species in place, keeping nature, moves, team slot, and ability when the evolution can have it.
**Look For tab:** realistically catchable species (no legendaries, mythicals, Ultra Beasts, Paradox Pokémon, Megas, or lines whose best capture rate is under 30) from families not owned, ranked by team-score gain (current team, or auto-built six), one per family. Names the stage to search for and the evolution line to it. Catch plan: Quick Ball turn 1; a roster member with False Swipe; sleep (×2.5) or paralysis (×1.5) move, respecting type and ability immunities; best ball (Net, Fast, Dusk, Timer, Dream, Ultra) with Gen 3–4 per-throw odds as an estimate.
**Auto-build:** if roster ≤ 6 take all; else greedy add by best marginal score, then swap hill-climb until no improvement.
**Opponent tab:** pick opponent from dex and optional ability. Rank the current team (or all owned).
- Offence value = best of (multiplier × 1.5 if STAB) across the member's attack options, with the opponent's ability applied.
- Incoming = highest multiplier from the opponent's own types against the member (member ability applied).
- Speed = member's effective Speed vs the opponent's base Speed.
- Score = 2·log2(max(offence, 0.1)) − 2·log2(max(incoming, 0.125)) ± 0.5 for faster or slower.
- Output: best and worst member with sentences such as "Ground STAB deals double damage (×2) to Gengar", "X's Water attacks deal quarter damage (×0.25)", "no damage (immune)", plus ability causes ("via Levitate"). Neutral hits listed separately. Learning tip: best member's learnable move (power ≥ 60) if effective damage is more than 1.2× its current best. Full order line.
- Assumption: opponent attacks only with its own-type moves.

## 6. UI requirements
- Mobile-first, light and dark themes, safe-area padding.
- Four tabs: Pokédex (roster and editing), Best Team (analysis and moves), Look For, Opponent.
- Editor: ability and nature up front; types, moves and base stats under a collapsed "Hack changes" section; Remove needs a second tap.
- Custom suggestion list (not native datalist, which covers the keyboard): up to 6 buttons directly under the input, prefix matches first, selection on pointerdown, input scrolled towards the top on focus, extra bottom padding so the page can scroll.
- Collapsible per-Pokémon editor; warnings in red.

## 7. Known limitations
- Types only plus basic abilities; no damage numbers, items, weather or terrain.
- Opponent stats are not editable; opponent assumed STAB-only.
- No share links, export or import, or multiple teams.
- Tested in a simulated browser only (jsdom), not on a real phone.

## 8. Suggested build plan
1. **Project:** TypeScript + Vite static site; pure logic modules (typeChart, abilities, scoring, opponent) separated from UI.
2. **Data script:** reproducible PokeAPI → JSON generator; commit outputs with a version stamp.
3. **Tests:** unit tests for the type chart, ability effects, scoring formulas, auto-build determinism, stat editing.
4. **Port prototype behaviour** (acceptance: matches section 5).
5. **Backlog:** opponent stat and ability edits; multiple saved teams; JSON export/import and share URL; more abilities; real-device mobile testing; accessibility pass.
6. **Backend (only if needed):** accounts and sync via Node and SQLite or Postgres.
**Risks:** hack data differs from vanilla; fan-project IP (Pokémon is Nintendo's); do not distribute ROM data; attribute PokeAPI. Scoring weights are heuristic and need user feedback.
**Success criteria:** works offline-capable on mobile, correct on known type matchups, an explanation shown for every ranking.
